# Wardrobe UX

ログイン後はクローゼットへ直行する。2列を標準に2/3/4列を保存でき、4:5画像、ブランド、商品名の順で表示する。カテゴリは上部のタップに加えて一覧部分の左右スワイプでも前後へ移動でき、選択中のカテゴリ名は見える位置へ追従する。検索はAppBar内、複合filterはbottom sheet、sortはmenuで完結する。

クローゼットが唯一の主画面なので、現在地を示すだけの下部「クローゼット」は置かない。下部は黒い「服を追加」ボタン1つにして、登録の入口を明確にする。

Drift cacheを先に表示してから同期し、refresh中や通信エラーでも既存一覧を消さない。画像領域を固定してlayout shiftを防ぎ、detailは同じnavigation stackに積んでscroll位置を保持する。登録後は完了画面を挟まず一覧へ戻す。

## 登録の速さ（写真から20秒）

写真から登録するときの入力負担を減らすため、エディタは「写真・商品名・カテゴリ・保存」だけを見せる構成にしている。

- 詳細（カラー表記、サイズ、価格、購入日、型番、SKU、購入店、メモ）は「詳細を入力」に畳む。開かなくても保存できる
- 保存はAppBarと本文末尾の両方にあり、スクロールしないと押せない状態を避ける
- 写真を選んだ直後に商品名へフォーカスし、キーボードを開く
- カメラ/ライブラリの選択は記憶し、2回目以降はシートを出さずに前回の方法で開く
- 保存後はスナックバーの「続けて撮る」で次の1枚に進める
- **カテゴリは選ばせない**。名前から `POST /api/classify` で推定して埋め、誤りはチップを1タップで直せる（未選択のまま保存することも可能）

## 属性とフィルタ

- **袖丈**（半袖 / 長袖 / ノースリーブ / 七分袖）はカテゴリと直交する属性として持つ。エディタではカテゴリの隣のチップで選べ、名前からAIが推定して未選択のときだけ埋める
- トップスまたはシャツの一覧では、カテゴリ直下に **すべて / 半袖 / 長袖 / ノースリーブ / 七分袖** を常時表示する。トップスとシャツの間では選択を維持し、それ以外のカテゴリへ移ると解除する
- フィルタは ブランド / カラー / 袖丈 / サイズ / 手放した服。袖丈を足したことで「半袖だけ」を1タップで見られる
- **サイズは表記ゆれを名寄せ**する（`M` / `Ｍ` / `Mサイズ` / `メンズM` は同じ）。ブランドと同じく比較キーでグルーピングし、表示は元の表記を残す

カテゴリは アウター / トップス / シャツ / パンツ / スーツ / シューズ / アクセサリー / その他。ニットはトップスに含める。オールインワン・つなぎ・ジャンプスーツ・カバーオールもトップスに含め、種類は細分類で残す。

## 画像の選択

URL取込では商品ページの画像が最大8枚入る。エディタのプレビューで、

- URL取込の直後に**画像選択モーダル**が開き、候補（最大40枚）から使う画像を選ぶ。既定は1枚だけ選択された状態
- 「画像を選ぶ（N枚から）」でいつでも開き直せる。複数選ぶと選んだ順に並び、**番号の小さい画像がメイン**（一覧の1枚目）
- 撮影した写真も候補に加わる

メイン画像には「メイン」バッジが付く。保存時の順序がそのまま `sort_order` になり、先頭が `is_primary` になる。

## 待たされるときの表示

URL取込（数秒）と保存（画像の取り込みと処理で数秒）は待ち時間が長い。処理中は画面全体を薄い白で覆い、スピナーと何を待っているかを出す。

- 商品情報を取得中…（URL取込・AI候補からの取込）
- 候補を探しています…（AI検索）
- 写真を準備しています…（カメラ/ライブラリ）
- 保存しています…（画像の取り込みと正規化を含む）

処理中は保存などの操作を無効化し、二重送信を防ぐ。
