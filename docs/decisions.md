# Decisions
## ADR-001: 認証とキャッシュ
Google subを外部Identityとし、RS256 JWKS検証後、aud/iss/exp付きHS256 JWTを7日発行。クライアントuserIdは信用しない。Drift行はuserIdで分離し、logout時に全ローカル行を削除する。進行中同期は世代番号で無効化。
## ADR-002: 画像（背景除去方式はADR-006で置換）
原本はprivate R2へ保存し、表示用画像とthumbnailを別キーで持つ。URL画像も原本アップロード後に端末で非同期処理し、失敗時は原本へフォールバックする。詳細画面では原本と処理済み画像を切り替えられる。当初採用したAndroid端末上のONNXセグメンテーションはADR-006で廃止した。
## ADR-003: URL取得
リダイレクト毎にURLとDNSの公開アドレスを検証、サイズと時間を制限。Workerの公開ネットワークfetchを利用し、HTTP/HTTPSのみ許可。決定的parserを優先し、不足時にのみResponses Structured Outputsを使用。AIは既存値を上書きしない。
## ADR-004: 最小構成
Riverpodによる依存注入、Dio、Drift、Navigatorによる画面stackを採用。小規模アプリに不要なcode generation/model hierarchyを追加しない。

## ADR-005: カテゴリを実際に着る物に合わせる
master-prompt §34 のカテゴリ一覧は網羅的だが、オーナー（男性・個人利用）はデニム・セットアップ・バッグ・オールインワン（ワンピースの受け皿）を使わない。使わないカテゴリがナビゲーションとチップに並ぶと、閲覧と登録のどちらも遅くなるため、削除して「スーツ」を追加した。

この時点のカテゴリ: アウター / トップス / シャツ / ニット / パンツ / スーツ / シューズ / アクセサリー / その他。現在の定義はADR-007で更新した。

削除したカテゴリを持つ既存itemは `other` へ寄せてから削除する（migration `0002_category_tuning.sql`）。ワンピース・スカートは追加しない。袖丈（長袖/半袖）はカテゴリと直交する属性なので、カテゴリには混ぜず別軸で扱う方針とする。

## ADR-006: 画像の背景除去をやめる
端末内ONNX（`image_background_remover`）による背景除去を削除し、4:5の正規化（向き補正・前景の外接矩形での切り出し・中央配置・余白・サムネイル生成）だけを残す。

理由:

- 実際に使うと精度が足りない（切り抜きの破綻、人物写真で頭部が不自然に切れる等）
- releaseビルドでR8がJNIから参照されるクラスを削除し、保存直後にプロセスごと落ちる不具合が発生した。keepルールで回避したがリスクは残る
- `libonnxruntime.so` だけで約33MBを同梱しており、配布サイズと起動負荷に見合わない

正規化だけでも一覧の統一感（§24）は保てる。原本は従来どおり保持し、詳細画面で整えた画像と切り替えられる。将来、服に特化した軽量モデルで品質が確保できたら復帰させる（実装はgit履歴に残っている）。

## ADR-007: ニットをトップスへ統合し、袖丈を一覧で切り替える
ニットは独立カテゴリとして使わないためトップスへ統合する。既存itemはmigration `0004_merge_knitwear.sql` で `tops` に移し、細分類が空なら「ニット」を残す。オールインワン・つなぎ・ジャンプスーツ・カバーオールも、専用カテゴリや「その他」ではなくトップスとして扱い、種類は `subCategory` に保持する。新規登録とURL取込では商品名による決定的な補正をAI結果の後にも適用する。

トップスとシャツは袖丈で探す頻度が高いため、一覧のカテゴリ直下に「すべて / 半袖 / 長袖 / ノースリーブ / 七分袖」を置く。両カテゴリ間では袖丈を維持し、袖丈の意味が薄い他カテゴリへ移ると解除する。詳細フィルタにも同じ袖丈軸を残す。

現在のカテゴリ: アウター / トップス / シャツ / パンツ / スーツ / シューズ / アクセサリー / その他。
